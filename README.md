# sports-dashboard

Backend for a live sports dashboard. You create matches through a REST API, they get stored in Postgres, and anyone connected over WebSocket gets told about the new match the moment it's saved.

There's no UI yet. That's coming later, so for now everything here is the server side: Express for HTTP, `ws` for the socket server, and Postgres through Drizzle ORM.

## Stack

- Node.js 24 + TypeScript (run directly with `tsx`, no build step)
- Express 5
- `ws` for WebSockets, sharing the same HTTP server as Express
- PostgreSQL 17 (via Docker Compose)
- Drizzle ORM and drizzle-kit for schema and migrations
- Zod for request validation
- pnpm

## How it works

The flow right now is pretty simple:

1. A client (the future dashboard, or just a browser tab for now) opens a WebSocket connection to `ws://localhost:8000/ws`. The server replies straight away with `{ "type": "welcome" }` so the client knows it's connected.
2. Someone creates a match by sending `POST /matches` with the teams, sport and start/end times.
3. The body is validated with Zod. Bad input gets a `400` back and nothing is written.
4. The server works out the match status from the times you sent. If the start time is in the future it's `scheduled`, if we're between start and end it's `live`, and if the end time has passed it's `finished`.
5. The match is inserted into the `matches` table.
6. The new row is broadcast to every open WebSocket client as `{ "type": "match_created", "data": { ...match } }`. Clients whose sockets aren't open are skipped, so one dead connection doesn't stop the others from getting the update.
7. The HTTP caller gets a `201` with the same match object.

When a client first loads (or reconnects), it should call `GET /matches` to get the current list and then rely on the socket for anything new after that.

```
 client ──POST /matches──▶ Express ──validate──▶ insert into Postgres
                                                      │
 dashboard(s) ◀──── ws: match_created ◀───────────────┘
```

## Project layout

```
src/
  index.ts              Express app, HTTP server, attaches the WS server
  routes/matches.ts     GET and POST /matches
  ws/server.ts          WebSocket server and broadcast helpers
  db/db.ts              pg pool + drizzle instance
  db/schema.ts          tables: matches, commentary
  db/migrations/        generated by drizzle-kit
  validation/matches.ts Zod schemas
  utils/match.status.ts works out scheduled / live / finished
demo_ws/                small standalone WS echo/broadcast demo I used to try out `ws`
```

`demo_ws` isn't part of the app. It runs its own socket server on port 8080 with a little HTML page for sending messages back and forth. I left it in as a reference.

## Getting started

You'll need Node 24, pnpm, Docker, and `tsx`. The npm scripts call `tsx` but it isn't in `package.json` yet, so install it globally (`npm i -g tsx`) or add it as a dev dependency.

```bash
pnpm install
cp example.env .env
```

The defaults in `example.env` line up with the Docker Compose setup, so you can leave them alone for local dev:

| Variable                                                             | What it's for                                           |
| -------------------------------------------------------------------- | ------------------------------------------------------- |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` | Used by Docker Compose to set up the Postgres container |
| `DATABASE_URL`                                                       | Connection string the app and drizzle-kit use           |
| `PORT`                                                               | Optional, defaults to `8000`                            |
| `HOST`                                                               | Optional, defaults to `0.0.0.0`                         |

Start Postgres and run the migrations:

```bash
docker compose up -d postgres
pnpm db:migrate
```

Then start the server:

```bash
pnpm dev     # watch mode
# or
pnpm start
```

You should see something like:

```
Server is running at localhost: http://localhost:8000
Websocket Server is running on ws://localhost:8000/ws
```

### Other scripts

- `pnpm db:generate` creates a new migration after you change `src/db/schema.ts`
- `pnpm db:studio` opens Drizzle Studio so you can poke around the data

## API

### `GET /matches`

Returns the most recent matches, newest first.

Query params:

- `limit` (optional): defaults to 50, max 100

```bash
curl "http://localhost:8000/matches?limit=10"
```

```json
{
  "data": [
    {
      "id": 1,
      "sport": "football",
      "homeTeam": "Arsenal",
      "awayTeam": "Chelsea",
      "status": "live",
      "startTime": "2026-10-07T14:00:00.000Z",
      "endTime": "2026-10-07T16:00:00.000Z",
      "homeScore": 0,
      "awayScore": 0,
      "createdAt": "2026-10-07T14:05:12.000Z"
    }
  ]
}
```

### `POST /matches`

Creates a match and broadcasts it to connected WebSocket clients.

| Field       | Type            | Required | Notes                     |
| ----------- | --------------- | -------- | ------------------------- |
| `sport`     | string          | yes      |                           |
| `homeTeam`  | string          | yes      |                           |
| `awayTeam`  | string          | yes      |                           |
| `startTime` | ISO date string | yes      |                           |
| `endTime`   | ISO date string | yes      | must be after `startTime` |
| `homeScore` | integer ≥ 0     | no       | defaults to 0             |
| `awayScore` | integer ≥ 0     | no       | defaults to 0             |

You don't send `status`. The server sets it from the times.

```bash
curl -X POST http://localhost:8000/matches \
  -H "Content-Type: application/json" \
  -d '{
    "sport": "football",
    "homeTeam": "Arsenal",
    "awayTeam": "Chelsea",
    "startTime": "2026-10-07T14:00:00Z",
    "endTime": "2026-10-07T16:00:00Z"
  }'
```

Responses:

- `201` with `{ "data": match }`
- `400` with `{ "error": "Invalid payload.", "details": "..." }` when validation fails
- `500` if the insert fails

## WebSocket

Connect to `ws://localhost:8000/ws`. Messages are JSON with a `type` field.

| type            | When                                        | Payload                    |
| --------------- | ------------------------------------------- | -------------------------- |
| `welcome`       | right after you connect                     | none                       |
| `match_created` | a match was created through `POST /matches` | `data`: the full match row |

Right now the socket only goes one way, server to client. Anything a client sends is ignored. Max message size is 1 MB.

A quick way to test from the browser console:

```js
const ws = new WebSocket("ws://localhost:8000/ws");
ws.onmessage = (e) => console.log(JSON.parse(e.data));
```

Then fire off the curl above and you'll see the `match_created` event show up.

## Database

Two tables so far.

`matches` holds the match itself: sport, home/away team, status (`scheduled | live | finished`, stored as a Postgres enum), start and end time, both scores and `created_at`.

`commentary` is for play-by-play events and links to a match through `match_id`. It has minute, sequence, period, event type, actor, team, the message text, a `metadata` jsonb column and a `tags` text array. The table exists, but nothing reads or writes to it yet.
